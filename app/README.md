# Приложение «Что нам приготовить?» — интеграция с базой блюд

```
app/
├── index.html    # приложение (фильтр кухонь строится из данных)
├── recipes.js    # 500 рецептов в формате RAW_RECIPES → RECIPES (425 КБ)
├── images/       # фото 150×150: images/<кухня>/<id>.jpg (3,9 МБ)
└── README.md
```

## Запуск

Просто открой `index.html` двойным кликом — всё локальное, интернет не нужен
(кроме шрифтов Google: без сети приложение отрисуется системным шрифтом).

Если браузер капризничает с `file://`, подними статику из папки `app`:

```bash
npx serve app        # или: python -m http.server 8000 --directory app
```

## Что изменилось в приложении

1. **Данные.** Вместо генератора фейковых рецептов — `recipes.js` из `data/`:
   500 реальных блюд, 8 кухонь: Русская 69, Европейская 69, Итальянская 55,
   Средиземноморская 55, Восточная 69, Азиатская 69, Кавказская 69,
   Американская 45.
2. **Фильтр кухонь.** Список строится из самой базы (`RECIPES.forEach` +
   `CUISINE_ICONS`), поэтому фильтр всегда совпадает с данными.
   Чтобы добавить кухню, добавь блюда с этим `cuisine` и иконку в `CUISINE_ICONS`.
3. **Фото.** Вместо фейковых ссылок `wsrv.nl/unsplash` — локальные картинки
   150×150 из `images/`. В карточке они круглые, в рецепте — 80×80,
   при ошибке загрузки срабатывает `onerror` и показывается эмодзи.
4. **Приёмы пищи:** «Завтрак», «Обед», «Ужин».
5. **Комбо «первое + второе» на обеде.** Исправлено: второе блюдо ищется по
   всей базе (в пуле обеда `isLightSecond` исключены), поэтому одинаковое
   блюдо дважды больше не выпадает. Если второго блюда для кухни нет,
   показывается только суп, без анимации тряски.
6. **Завтрак — только лёгкое и быстрое.** В «Завтрак» попадают блюда, которые
   реально едят утром: не больше **40 минут** готовки, не больше **350 ккал**,
   без мяса и рыбы. Итого 59 блюд (4–13 на кухню): каши, блины, оладьи, сырники,
   драники, круассаны и сконы, брускетта, хумус, лабне, шакшука, онигири, роти-чанай,
   хачапури-подобные кутабы, халлуми, сырники, компоты и морсы.
   Тяжёлое и долгое (пироги, торты, кулебяка, медовик) в завтрак не попадает:
   выпечка и десерты уходят в «Ужин», горячее — в «Обед/Ужин».
7. Остальное (рулетка, свайпы, шторка, вибрация) не тронуто.

## Формат данных

`recipes.js` ровно в том формате, который ждёт приложение:

```js
const RAW_RECIPES = [[name, emoji, time, difficulty, servings, meals,
                      cuisine, image, ingredients, steps, flag1, flag2], ...];
const RECIPES = RAW_RECIPES.map(r => ({ ... }));
```

- `meals` — массив из `"Завтрак" | "Обед" | "Ужин"`.
- `flag1 = "isLightSoup"` — лёгкий суп, на обеде запускает комбо «первое + второе».
- `flag2 = "isLightSecond"` — второе блюдо для комбо; в рулетке обеда такие
  блюда исключаются (логика приложения).
- `image` — путь относительно `index.html`: `images/russian/borscht.jpg`.

## Что сгенерировано, а что реально

| Поле | Источник |
|---|---|
| `name`, `ingredients` | реальные данные из `data/*.js` |
| `image` | реальные фото Викисклада, 150×150, лицензии в `data/credits.json` |
| `steps` | настоящие рецепты для 60 популярных блюд (`data/steps.json`), для остальных — шаблон по категории |
| `emoji` | по категории блюда |
| `time`, `difficulty`, `servings` | по блюду: быстрые завтраки 5–35 мин, долгие (торты, плов, пельмени) 70–120 мин |
| `meals` | по категории: супы — обед, выпечка — завтрак, горячее — обед/ужин и т.д. |

Количества ингредиентов («500 г», «2 шт.») сгенерированы по правилам — для
продакшена их стоит заменить авторскими. Всё остальное — из базы.

## Пересборка

```bash
node scripts/build-app-recipes.js   # пересобрать recipes.js и скопировать фото
node scripts/check-app.js           # проверить: данные, фото, пулы фильтров, комбо
node scripts/smoke-app.js           # дымовой тест на DOM-заглушке
```

Проверка выводит таблицу «кухня × приём пищи» и падает, если какой-то фильтр
даёт пустой список или комбо находит второе блюдо в той же кухне.
